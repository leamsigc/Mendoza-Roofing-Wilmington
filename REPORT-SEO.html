✅ Completed — Round 3: Indexing Investigation (83 non-indexed pages)

Diagnosis from GSC Page Indexing report (53 indexed / 83 not): 56 "Discovered – currently not indexed", 9 "Page with redirect", 8 "Crawled – currently not indexed", 7 "Duplicate, Google chose different canonical", 3 "Alternate with proper canonical". Three root causes found and fixed:

✔Root cause #1 — 40 Spanish pages were empty meta-refresh shells. Pages with no ES translation (e.g. /es/southport-nc-roofing) were prerendered as bare <meta http-equiv="refresh"> stubs — no title, no canonical, no content. Google crawled them from the sitemap and flagged them "Duplicate, chose different canonical" (all 7 duplicates were /es/ pages) and "Crawled – not indexed". Fix: new scripts/generate-redirects.mjs scans the build output and converts all 65 shells into real 301 redirects via a Netlify _redirects file — Google now consolidates them cleanly instead of indexing stubs.
✔Root cause #2 — hreflang was completely missing site-wide. i18n.baseUrl pointed to an undefined env var (process.env.NUXT_PUBLIC_BASE_URL — not set in Netlify), and useLocaleHead() was never called. Google had no language signals, so it folded ES pages into EN. Fix: hardcoded the baseUrl and added useLocaleHead({dir,lang,seo}) in app.vue — every page now emits x-default / en / en-US / es / es-ES alternates (verified in build output).
✔Root cause #3 — broken Netlify publish config. netlify.toml declared publish = "dist" but dist is a gitignored local symlink that doesn't exist in Netlify's build. Fix: publish now points to the real Nitro output (.output/public) and the build command generates the redirects file automatically. (Corrected after first deploy attempt: Nitro's Netlify preset outputs public files to dist/ and writes its own _redirects with a /* /404.html 404 catch-all — so the final config restores publish = "dist", keeps Nitro's catch-all, and the redirects script prepends the 65 shell 301s before it, idempotently, in the correct first-match-wins order. The dead /* → /index.html 200 SPA rewrite was removed — it could have soft-404'd unknown URLs into the homepage.)
✔Trailing-slash entries in "Crawled – not indexed" (/services/, /blog/, 2 blog posts): verified they 301 correctly to the canonical non-slash URLs — stale crawl entries, self-healing, no action needed.
✔What "Discovered – currently not indexed" needs: it's a crawl-priority queue, not an error. The money pages in it (/commercial-roofing-wilmington-nc, /emergency-roof-repair-wilmington-nc, /blog/roof-replacement-cost-wilmington-nc, /contact) should be re-inspected and "Request indexing" in GSC after deploy — the fresh lastmod dates from today's builds will pull the rest of the queue.

Expected effect: the 7 duplicate-canonical ES flags resolve to redirects; crawl budget stops leaking into 65 empty shells; ES pages with real content gain hreflang signals to rank in Spanish.
